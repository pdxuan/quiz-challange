## Design choices made while building

- `GET /api/quiz-sets` projects straight to `{id, title, questionCount, timeLimitSec}` in SQL,
  ordered by title; no question, option or answer data is ever loaded.
- `SeedValidator.Validate(QuizSet)` returns every broken rule as a message (empty = valid):
  exactly 4 options, unique option ids, unique option texts (case and spaces ignored), a correct
  option that exists, a non-empty prompt and option texts, at least one question, a positive time
  limit, unique question ids and positions, and at most one direction per word (the word is the
  prompt for word -> meaning and the correct option for meaning -> word).
- `DevSeeder` seeds only when the database has no users, quiz sets or sessions; it validates
  every set first and refuses to start the app with an invalid seed file. Passwords in
  `users.json` are dev mock data, hashed at startup with `PasswordHasher<User>`. The JSON is read
  from `ContentRootPath/Seed/seed`, so the csproj is unchanged.
- Seeding runs only in Development and only while `Seed:Enabled` is not `false` (default on).
  The flag exists because the shared test host also runs in Development on an empty database:
  with seeding on, every test that creates its own `alice` hit the unique username index
  (56 of 209 tests failed). The test host sets `Seed:Enabled=false` (one TRUNK line in
  `TestHost/QuizApiFactory.cs`, added by the main session; the interviewer moved S6 to the TRUNK
  lane for it); the seed tests switch it back on with their own factory subclass.
- E2E driver (`tests/.../EndToEnd/E2ESession.cs`): the organizer logs in and creates the session
  over REST and watches it over the hub; players log in and join over the hub; a fixed `Random`
  seed plans each player's move per question (answer at a 100 ms step, answer late, or nothing).
  All answers due at one time are sent at once; the fake clock moves between them. One player
  per question is always late, so every question ends at its deadline and the 3 sessions stay in
  lockstep on the shared fake clock.
- Expected results come from the inputs, not the server: the `Answers` rows must equal the
  accepted answers scored with `Scoring.Points(correct, limit - sentAt, limit)`; totals are
  summed from the rows and ranks recomputed (competition ranking) and compared with every
  player's `QuizFinished` and the organizer's board.

## What the AI got wrong or had to correct

- The first plan for seeding (Development + empty DB) would have broken most existing tests,
  because the test host is also Development with an empty DB. Shown by running the suite: 56
  failures (`DbUpdateException`, unique username). Fixed with the `Seed:Enabled` flag; the
  matching test-host line is TRUNK, so the worker left it to the main session (the parallel
  plan had wrongly assumed S6 needed no TRUNK file).
- The E2E "no errors logged" check failed at first: SignalR's `DefaultHubDispatcher` logs every
  `HubException` at Error level, so each planned late answer (`QuestionClosed`) produced an
  error entry. The check now allows exactly one such entry per late answer and nothing else.
  (A log filter for that category would belong to `Observability/`, TRUNK; noted as a follow-up.)
- Two compile errors in the first test draft: a missing `Microsoft.AspNetCore.SignalR.Client`
  using for `HubConnection.On<T>`, and `Domain.QuestionDirection` resolving to the test
  namespace.
