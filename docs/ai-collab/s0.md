## What the AI got wrong or had to correct

- The `dotnet new xunit` template adds `coverlet.collector`, which was not on the approved
  package list; removed.
- On .NET 10, `dotnet new tool-manifest` writes `dotnet-tools.json` at the repo root, not under
  `.config/` as planned; moved to `.config/dotnet-tools.json` (dotnet still finds it there).
- Three web packages needed by the approved ones were missing from the list (`@types/react`,
  `@types/react-dom`, `@testing-library/dom`); asked before installing them.
- A plain `MapFallbackToFile` would also have answered `/api/...`, `/swagger` and `/openapi`
  with the SPA page (200). The tests were written to catch that, and the server maps those
  prefixes to a 404 ProblemDetails first.

## How it was verified

- Tests seen red first: 9 of 12 server tests failed for the expected reason (no OpenAPI,
  Swagger, health or SPA fallback yet); the web test failed because `./App` did not exist.
- Then green: `dotnet test Quiz.slnx` 12 passed; `npm --prefix web test -- --run` 6 passed;
  `npm --prefix web run build` writes the SPA into `src/Quiz.Server/wwwroot`.
- The production 404 tests guard against the SPA fallback swallowing server paths.
- Manual: `dotnet run` in Development, `/swagger` and `/health` requested (see the PR).
