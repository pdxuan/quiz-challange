# S5 Web client - AI collaboration notes

- Tool: Claude Code (Claude Opus 5.5), a worker agent in its own git worktree, dispatched by the
  main session for `/build S5` (in parallel with S6).
- Task: the React client in `web/`: REST client, a hub client behind an interface (plus a fake
  for tests), login, home (join by quiz ID), organizer setup and live views, player view.
- Prompt style: the S5 block in docs/PLAN.md, the Contract (REST, hub, events, UI routes) and D1
  in docs/TASK.md, and the server's `PlayContracts.cs` for the exact payloads; tests first,
  through the whole `App` with a fake `fetch` and a fake hub, no mocks of our own components.

## Design choices made while building

- `src/api/client.ts`: one `request` helper; a failure throws `ApiError(status, code)` where the
  code is the ProblemDetails `title` (e.g. `NoPlayers`), so the views switch on codes, not text.
- `src/realtime/hub.ts`: `QuizHubClient` interface (`connect`, `disconnect`, `joinQuiz`,
  `watchQuiz`, `submitAnswer`, typed `on`, `onClose`), the SignalR implementation, and a React
  context holding a factory so each view creates its own client and tests inject
  `FakeQuizHub`. `hubErrorCode` takes the code after `HubException: `; `errorMessage` maps
  every hub and REST code to a readable sentence (unknown failure -> `ServerError`).
- `onClose` fires only for a drop, not for our own `disconnect` (unmount), so leaving a page
  never shows "Connection lost". No auto-reconnect (Not building): Rejoin reconnects the same
  client and calls `JoinQuiz` / `WatchQuiz` again.
- Countdown: when a question arrives, the local deadline is fixed as
  `Date.now() + (endsAt - serverNow)`; the timer only counts down to it. The client clock never
  sets the deadline itself.
- `RequireUser` wraps `/`, `/host`, `/host/:quizId` and `/play/:quizId`: it calls
  `GET /api/auth/me` and sends a 401 to `/login`.
- Player view: one reducer with phases lobby -> question -> (locked in) -> reveal -> final,
  plus `waiting` (rejoin during a reveal), `rejected` (join error with its reason) and a `lost`
  flag shown on top of the current phase. Options are disabled once one is chosen or when the
  player joined mid-question (`canAnswerCurrent = false`); the next `QuestionStarted` enables
  them. Close/finish payloads are told apart by shape (`correct` / `rank` for a player,
  `leaderboard` for the organizer).
- Organizer view: the snapshot from `WatchQuiz` fills the state (so a reload or Rejoin resumes
  in any phase); events then update players, question, answers in / eligible, the full board
  after each close, and the podium (places follow the shared ranks, so a tie shows 1st, 1st,
  3rd) plus full standings at finish. Start is enabled only with >= 1 player; a REST error such
  as `NoPlayers` is shown.
- Test helpers live with the code they fake: `src/api/fakeFetch.ts` and
  `src/realtime/fakeHub.ts` (plain TS, no Vitest imports, so `tsc -b` builds them).
- `App.test.tsx` still renders every route and checks its heading; it now stubs `/api/auth/me`
  and the hub because each view is real.

## What the AI got wrong or had to correct

- Nothing failed after the first implementation; the tests were then checked against mutants
  (below) so a green run is not a test that checks nothing.
- A first podium draft labelled places by list position; changed to the shared rank so ties
  are shown honestly.
- Reviewer agent (Should, all picked by the interviewer; fixed in a follow-up commit, tests red
  first where behaviour changed):
  - Start was enabled with any player, but the server needs one *online* player (`NoPlayers`),
    and the "rejected start" test had locked that mismatch in. Start now needs an online player;
    a new test keeps it disabled while everyone is offline (red first), and the rejected-start
    test now uses an online player.
  - Every rejected answer re-enabled the options, even for final codes (`QuestionClosed`,
    `AlreadyAnswered`, `NotEligible`, `NotCurrentQuestion`). Now only `Invalid` and
    `ServerError` free them (4 new cases red first; a `ServerError` case guards the retry).
  - The host view imported `Countdown` from the play view (view-to-view dependency). Moved
    `Countdown`/`timed` to `web/src/realtime/` with its own CSS module.
  - R14: the significant web files now carry a first-line `// AI-assisted:` marker.

- Mutations (applied, web tests run, restored):
