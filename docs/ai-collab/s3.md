# S3 Session actor and sessions API - AI collaboration notes

- Tool: Claude Code (Claude Opus 5.5), main session, `/build S3`.
- Task: one actor per session (channel, load-apply-save per call, timer `Tick`), the registry,
  recovery after a restart, the `ISessionEvents` port for S4, and `POST /api/sessions`,
  `POST /api/sessions/{quizId}/start`, `GET /api/sessions/{quizId}/leaderboard`.
- Prompt style: the S3 block in docs/PLAN.md, approach A and the key flow in docs/TASK.md;
  tests first, time driven by `FakeTimeProvider`.

## Decisions

- Interviewer: while a question is open, the leaderboard leaves out that question's points
  (results only at close, D1). The rule lives in `Session.Leaderboard()`, so REST and the hub
  share it; it needs the session's answers loaded (the actor and the read both load them).
- A call is a function `(Session, SessionCall(Now, Rules)) -> T` posted to the actor, not a
  message class per command: one generic path for load, apply, save, publish, reply.
- `ISessionEvents.Publish` is called after the commit and must not block; until S4 a no-op is
  registered. The actor never awaits a push.
- Ticks are coalesced (at most one queued) so a long clock jump does not queue hundreds of loads;
  one tick makes one transition (S1), so a reveal is never skipped.
- The actor stops when its session is finished or missing; the registry starts a fresh one on
  the next call. A finished session is still readable from SQLite.
- `QuizNotFound` joined the domain's error codes (it is a Contract code).
- Error codes are the ProblemDetails `title` (`NotOrganizer` 403, `NotInLobby`/`NoPlayers` 409,
  `QuizNotFound` 404); an unexpected failure is a 500 with no detail and is logged with quizId.
- Outside the S3 Files list (all TRUNK): `Domain/` (leaderboard rule, `QuizNotFound`,
  `RankedPlayer.TotalPoints`), `TestHost/` (fake time, event recorder, log capture, restart on
  the same files), one `AddQuizRuntime` line in `Program.cs`, and the approved
  `Microsoft.Extensions.TimeProvider.Testing` package in the test project.

## What the AI got wrong or had to correct

- Reviewer agent (Must): recovery awaited every session without a catch, so one unreadable
  session made the whole server fail to start (against AC28). Now each session is resumed in
  its own try/catch and a failure is logged with its quizId; a test with a corrupted `Phase`
  row was seen red (host failed to start) before the fix.
- Reviewer agent (Should, picked by the interviewer), each with a test seen red first unless noted:
  (1) idle Lobby actors kept a 100 ms clock that loaded the session forever, and recovery
  revived every abandoned Lobby on each restart -> the actor now stops when its session is not
  Running; (2) an unreadable session made every tick log an error, about 10 per second -> the
  actor stops after 3 failures in a row (not after one, so a Running quiz survives a brief DB
  hiccup); (3) a stopping actor left the registry before its queue drained, so a second actor
  could write the same session -> it leaves only after draining, and a new call waits for it
  (no deterministic test; covered by review); (4) a restart during an overdue reveal finished
  the quiz before anyone could reconnect -> `Session.Resume` gives a full reveal from the
  restart (interviewer chose this); (6) the events port moved to its own file for S4.
- Adding a tuple overload `Ranking.Rank(...)` made `Ranking.Rank([])` in an existing test
  ambiguous (CS0121); renamed the overload to `RankStandings` instead of touching the test.
- The domain leaderboard test was written first but only run after the change (the test project
  could not compile until Runtime existed); the red was shown afterwards by reverting the rule
  (mutation M1 below).

## How it was verified

- Tests seen red first: the test project did not compile without `Quiz.Server.Runtime`
  (`SessionRegistry`, `ISessionEvents`); behaviour reds shown by the mutations below.
- Then green: 162 server tests (36 new, incl. a broken session skipped at recovery and stopped
  after 3 failures, Lobby actors stopping, a restart during an overdue reveal): create/start/leaderboard incl. 400/401/403/404/409,
  OpenAPI paths, tick close -> reveal -> next -> finished, unknown quiz, rule failure saves
  nothing, failing save rolls back + logs quizId + next call works, two answers at once store
  one, 2 sessions x 20 concurrent joins, restart resume with a rejoin, restart with nobody back,
  recovery of a Lobby.
- Mutations (applied, tests run, restored with `cp`):
