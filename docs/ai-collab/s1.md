# S1 Domain rules - AI collaboration notes

- Tool: Claude Code (Claude Opus 5.5), main session, `/build S1`.
- Task: the pure `Session` state machine (join/rejoin, start, answer, close, reveal, finish,
  disconnect, all offline), `Scoring`, `Ranking`, `QuizIdGenerator`, error codes and events.
- Prompt style: the S1 block in docs/PLAN.md and the Assumptions/Contract rows of docs/TASK.md
  as the spec; tests first with an explicit `now` (no clock, no sleeps).

## Design choices made while building

- Rule failures throw `SessionException` with a `SessionError` whose names are the Contract
  codes; the actor (S3) maps them to replies. Changes are collected in `Session.Events` and
  pushed only after the save commits.
- Capacity and reveal time come in as `SessionRules` (from config), not stored per session, so
  the schema in TASK.md stays unchanged.
- `Start` needs at least one *online* player: starting with only offline players would finish
  the quiz at once under the all-offline rule.
- A finished session answers `QuestionClosed` to a late answer (no separate code in the Contract).
- `Tick` makes one transition per call, so a long pause (or a restart) never skips a reveal;
  after `MarkAllOffline` (restart) the quiz finishes at the next phase end if nobody rejoined.
- Check order in `SubmitAnswer`: a retry with the same `submissionId` returns the original result
  even after the deadline; then closed, then already answered, then eligibility, then option.

## What the AI got wrong or had to correct

- One expected value in a test was miscomputed (933 instead of 967 for 14 s left of 15); caught
  while re-deriving the numbers before the first run.
- Reviewer agent (Must): after a restart, the first `Tick` on an overdue question closed it *and*
  finished the quiz in one call, so nobody could rejoin - against the restart Assumption and
  the "one transition per tick" rule. My own test had locked that in (it only checked a question
  that was not overdue). Fixed: the Question branch only closes; the quiz finishes at the end of
  the reveal if nobody is online. Tests added for the overdue close, a rejoin during the reveal,
  and nobody rejoining; seen red (3) before the fix.
- Reviewer agent (Should, picked by the interviewer): (1) a client retrying `JoinQuiz` on the
  same connection got its own connection back as "replaced", which S4 would have removed from
  the group; (2) the organizer's "answers in / eligible" went stale when an eligible player
  disconnected or rejoined mid-question; (3) a quiz set without questions crashed `Start` with
  `ArgumentOutOfRangeException`. Each got a test seen red first, then the fix.
- `RankingTests` needs to set points directly, but the setters are `internal` so that only
  `Session` changes scores; solved with `InternalsVisibleTo` in `Domain/` instead of public setters.

## How it was verified

- Tests seen red first: the test project did not compile because `Quiz.Server.Domain` did not
  exist (CS0234/CS0246).
- Then green: 82 domain tests (95 with the skeleton) - scoring, ranking, quiz IDs, join, answer,
  lifecycle, including 20 players in one question with totals and ranks recomputed in the test.
- Mutation check on `Scoring` (each mutant applied, tests run, code restored):

  | Mutant | Domain tests failing |
  |--------|----------------------|
  | `MidpointRounding.ToEven` instead of `AwayFromZero` | 2 / 76 |
  | no clamp of `remaining` to [0, limit] | 2 / 76 |
  | wrong answers score like right ones | 4 / 76 |

- `Domain/` uses only the BCL (`System.Runtime.CompilerServices`, `System.Security.Cryptography`);
  no ASP.NET Core or EF Core reference (grep).
