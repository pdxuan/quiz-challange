# S2 Data and auth - AI collaboration notes

- Tool: Claude Code (Claude Opus 5.5), main session, `/build S2`.
- Task: EF Core SQLite (`QuizDbContext`, Fluent mapping of the S1 domain classes, initial
  migration, WAL, migrate at startup), cookie auth with login/logout/me, a DB health check, and
  test hosting on a temp SQLite file per factory.
- Prompt style: the S2 block in docs/PLAN.md, the schema and Contract rows of docs/TASK.md;
  tests first. Two schema questions went to the interviewer before the migration was written.

## Decisions made with the interviewer

- `Options` key is `(QuestionId, OptionId)` (ids "a".."d" repeat per question) and `Answers`
  has a composite FK to it, so the database itself rejects an option of another question.
- `Questions.CorrectOptionId` has no FK (it would be circular with `Options`); the seed
  validator (S6) and the domain check it.

## Design choices made while building

- Deny by default: an authorization fallback policy needs a logged-in user on every endpoint;
  login, logout, health, OpenAPI and the SPA/404 fallbacks opt out with `AllowAnonymous`. The
  hub (S4) and session endpoints (S3) are protected without extra code.
- The cookie answers 401/403 instead of redirecting; the empty 401 becomes ProblemDetails
  through `UseStatusCodePages`.
- Wrong password and unknown user give the same 401 "Wrong username or password".
- `User` lives in `Data/` (no domain rules); passwords use ASP.NET Core's `PasswordHasher<T>`
  (shared framework, no package).
- A relative SQLite path is resolved under the content root; the folder is created at startup.
- The health check opens the DB with `CanConnectAsync`; no extra health-check package.

## Reviewer findings fixed (picked by the interviewer)

- The plan asked for a `DateTimeOffset` converter and a busy timeout; neither was there (the
  code relied on `TimeProvider` giving UTC and on the provider's 30 s default). Added a UTC
  converter and an explicit 5 s timeout, each with a test seen red first.
- `Answers -> Questions` was a redundant FK; removed. All FKs cascaded; the ones that point out
  of a session (quiz set, user) and `Answers -> Options` are now `RESTRICT`, with tests that a
  used quiz set or user cannot be deleted. The initial migration was regenerated (not merged
  yet, so no second migration).
- AC4 is only provable for endpoints that exist; S3, S4 and S6 add their own 401 tests.

## What the AI got wrong or had to correct

- `Logout(HttpContext) -> Task<IResult>` bound as a `RequestDelegate` (ASP0016) and dropped the
  result; fixed by casting to `Delegate`.
- The first `migrations script` run used `--no-build` against a stale DLL and printed only the
  history table; re-run with a build.
- A duplicate-key test first expected EF's change tracker to fail at `SaveChanges`; the
  tracker throws at `Add`, and it would not have tested the database anyway. Rewritten to use
  two contexts so the SQLite primary key has to reject it.
- After the health-check mutation, restoring the file with `mv` from a backup kept an *older*
  timestamp than the mutated build, so MSBuild skipped the rebuild and the 503 test kept failing
  against the stale DLL. `touch` + rebuild fixed it; mutations are now restored with `cp`.
- A collection expression used as a receiver (`["a", ...].Select`) does not compile (CS9176).

## How it was verified

- Tests seen red first: the test project did not compile without `Quiz.Server.Data` /
  `QuizDbContext` (CS0234/CS0246).
- Then green: 126 server tests (31 new, incl. UTC storage, busy timeout, Answers FKs, restrict deletes; schema, keys, WAL, model = migrations, round trip,
  duplicate answer, option of another question, case-insensitive unique username, health
  200/503, login/me/logout, 401/400 paths, OpenAPI lists the auth endpoints).
- Mutation: removing the DB health check registration makes the 503 test fail.
- The migration SQL was printed with `dotnet ef migrations script` and read table by table.
